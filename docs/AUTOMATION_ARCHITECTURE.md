# 持续数据发现与算法迭代架构

## 1. 目标与边界

目标不是无限下载 STEP，而是持续补充当前语料没有覆盖或覆盖不足的几何族，并用固定证据判断算法候选版本是否同时提高准确性、稳定性和效率。

系统分类的是几何等价 Solid，不会把文件名中的“螺钉”“轴承”当作几何真值。名称只用于发现方向；最终准入、分组与准确率证据仍来自 OCCT 结构检查、独立 B-Rep 精确层和人工标签。

## 2. 自动化成熟度评估

成熟度定义：L0 手工；L1 有脚本；L2 可重复的单机流程；L3 有状态、失败隔离和质量门禁；L4 可持续闭环；L5 无人值守自动晋级。

| 能力 | 整理前 | 当前 | 仍需人工的原因 |
|---|---:|---:|---|
| 来源发现 | L1 | L3 | GitHub 搜索宜配置令牌；未知许可必须人工裁决 |
| 覆盖缺口判断 | L0 | L3 | 功能语义只能由名称提供弱证据 |
| 下载、哈希与原始证据 | L3 | L4 | 来源失效或许可变化需复核 |
| 多 Solid 准入 | L3 | L4 | 极端退化 B-Rep 仍可能需要 CAD 专家 |
| 分类与精确终审 | L3 | L4 | 超时关系采用保守拆分并进入复核 |
| 稳定性验证 | L2 | L4 | 需要定期扩展留出装配 |
| 参数效率优化 | L0 | L3 | 自动提出候选参数，但不自动改生产默认值 |
| 准确率估计 | L2 | L3 | 没有人工标签时不能宣称 precision/recall |
| 版本晋级 | L0 | L3 | 只有所有机器门禁和人工置信区间通过才可晋级 |
| 跨电脑接管 | L1 | L4 | 首次仍需安装 Python 与 Open CASCADE |

刻意不追求 L5。让同一个算法自动生成伪真值并批准自己会形成反馈污染；许可判断和最终几何歧义也不适合无人值守放行。

## 3. 双闭环架构

```text
数据闭环
本地语料 → STEP PRODUCT 名称 + 几何覆盖签名 → 覆盖不足类型
        → GitHub/Zenodo 定向搜索 → 许可/大小/格式门禁
        → 下载与哈希 → OCCT 多 Solid 准入 → 新语料/明确缺口

算法闭环
固定 Boolean-final 基准 → 候选阈值赛跑 → 计算量/精确组召回
        → 顺序、阈值、刚体不变性 → 分层人工抽检
        → 95% 置信区间门禁 → 可晋级 / 拒绝 / 等待标签
```

两个闭环通过版本化证据通信，不共享“结论”。发现器的关键词不能让分类器通过，候选描述符也不能让精确层通过。

## 4. 覆盖模型

覆盖包含两种互补证据：

1. **语义名称覆盖**：从 STEP `PRODUCT` 名称和源标识匹配配置中的类型词表。每类至少由多个独立装配覆盖，单一来源只算“覆盖不足”。
2. **几何分布覆盖**：对体积、表面积、面/边/点数做粗粒度稳定分箱。签名仅用于发现稀有区域，不能代替分类描述符或真值。

`config/continuous_iteration.toml` 是唯一策略入口。新增目标类型、同义词、最低独立来源数、文件大小和许可白名单都应改配置，不应散落在脚本中。

## 5. 联网发现与准入

发现适配器当前支持 Zenodo 和 GitHub：

- 只针对 `coverage_gaps` 搜索，避免重复堆积机器人和 3D 打印机数据；
- 每次查询、失败、认证状态和候选数均写入审计日志；
- 只有 STEP/STP、许可在白名单且未超过大小上限的文件可进入机器暂存；
- GitHub 代码搜索需要通过环境变量 `GITHUB_TOKEN` 提供只读令牌；未配置时明确记录认证缺口，令牌不会写入日志或仓库；
- 未知许可、网页模型、压缩包和需要登录的来源进入人工队列，不会被静默替代；
- 下载后仍必须通过哈希归档、STEP 文件头、OCCT 回读和最少 Solid 数门禁。

暂存不等于录用。每个周期最多录用配置规定的数量，防止一次搜索耗尽磁盘与布尔计算预算。

## 6. 效率优化与准确性

`optimize` 复用已完成运行的 `similarities.csv` 和 Boolean-final 分组，对多个候选阈值计算：

- 精确结果中同组配对被候选层覆盖的比例；
- 预计需要进入精确层的候选配对数量；
- 候选同组、精确层拆开的额外工作量。

推荐规则是在精确同组配对召回达到配置门限的方案中，选择候选配对工作量最小者；相对当前基线的降幅还必须超过最小实质收益门限，避免为统计噪声或几十个配对引入新参数。推荐结果只是一项实验提议，还必须在独立留出装配上重跑 Boolean 层。

显式运行 `python3 -m iteration_engine.cli benchmark` 会在配置指定的留出装配上执行候选阈值，比较 Boolean-final 分区 ARI 与实测运行时间。该步骤可能耗时很长，因此普通周期不会隐式启动。

算法晋级要求同时满足：输入顺序 ARI、阈值平台 ARI、刚体不变性、最低完成装配数、人工合并精确率及其 95% 下限、随机跨组正确拆分率及其 95% 下限。缺少人工标签时状态只能是 `waiting_for_human_labels`。

## 7. 可恢复状态与失败语义

每个周期把阶段命令、开始/结束时间、耗时、返回码和输出尾部原子写入 `research/iterations/latest_cycle.json`。下载和分类继续使用已有断点与精确关系检查点。任何强制阶段失败都会中止后续有状态操作，但覆盖报告和失败日志仍保留。

以下状态必须区分：

- `staged`：通过机器许可/大小门禁，尚未结构准入；
- `admitted`：OCCT 可读取且 Solid 数达标；
- `completed`：Boolean-final 分类完成；
- `unresolved`：精确关系超时或对齐失败，保守拆分；
- `eligible_for_promotion`：所有机器和人工门禁通过；
- `waiting_for_human_labels`：机器门禁通过但准确率证据不完整；
- `rejected`：至少一个强制门禁失败。

## 8. 操作方式

查看计划和当前覆盖：

```bash
python3 -m iteration_engine.cli plan
python3 -m iteration_engine.cli coverage
```

执行一次联网发现，但不下载：

```bash
GITHUB_TOKEN=... python3 -m iteration_engine.cli discover
```

执行完整新数据周期：

```bash
python3 -m iteration_engine.cli cycle --acquire --classify
```

离线复算覆盖、效率建议与晋级门禁：

```bash
python3 -m iteration_engine.cli cycle --offline
```

单独查看优化和晋级结论：

```bash
python3 -m iteration_engine.cli optimize
python3 -m iteration_engine.cli benchmark
python3 -m iteration_engine.cli evaluate
```

周期命令可由操作系统计划任务或 CI 调用。联网、下载和长时间 Boolean 分类必须由调用方显式启用；普通测试不会访问网络。

## 9. 跨电脑接管

仓库提交源清单、许可与选择审计、配置、代码、测试和协议，不提交外部原始模型、逐零件缓存、运行目录或人工复核图片。新电脑按以下顺序恢复：

1. 安装 Python 3.11+ 与 Open CASCADE `DRAWEXE`；
2. 可选安装人工复核依赖：`pip install -e '.[review]'`；
3. 运行 `python3 scripts/acquire_assembly_data.py` 从版本化清单恢复数据；
4. 运行检查、分类与评估命令重建所有带本机路径的证据；
5. 使用 `python3 -m unittest -v` 验证实现。

原始文件的 URL、期望大小和已知 SHA-256 保存在 `research/assembly_sources.json`；外部来源失效时，日志应记录为缺口，不应上传受第三方许可约束的副本来掩盖问题。
