# 架构与迭代契约

## 目标

系统将“候选发现”和“精确判定”分开。特征算法可以快速迭代，但最终结果必须经过与特征向量独立的 B-Rep 精确层，并通过数据、分组和导出三类质量门禁。

```text
STEP 源文件
  → OCCT 标准化/拆件
  → 数据质量检查
  → 可解释描述符与距离矩阵
  → complete-link 候选组
  → 刚体对齐森林
  → 双向布尔差终审
  → 最终组
  → STEP 导出与回读验证
  → 带哈希的可审计产物
```

## 模块边界

- `config.py`：唯一运行配置模型，在启动前校验参数。
- `occt_backend.py`：隔离 OCCT/DRAW 进程、精确质量属性、布尔运算与 STEP 输入输出。
- `step_graph.py`：将标准化 STEP 解析成属性面邻接图及无训练描述符。
- `similarity.py`：距离通道、尺寸门控和可解释分解。
- `clustering.py`：确定性 complete-link 候选分组。
- `precision.py`：不依赖候选向量的刚体对齐、镜像拒绝和精确关系森林。
- `workflow.py`：编排阶段、质量门禁、产物和失败语义；不实现几何算法。
- `telemetry.py`：原子更新运行清单、事件日志、环境与产物哈希。

## 不变量与质量门禁

1. 源数据：必须至少有一个 Solid；默认不允许未识别曲线/曲面类型静默混入。
2. 距离：必须有限、对称、对角为零且落在 `[0, 1]`。
3. 分组：每个输入索引必须恰好出现一次；精确层只能拆分候选组。
4. 精确层：旋转矩阵的行列式必须为正；超过顶点或布尔容差的关系不得联合。
5. 导出：所有组的回读 Solid 数之和必须等于输入数；单组数量、体积和 B-Rep 合法性必须通过。

任一强制门禁失败时，流水线以非零状态结束，`workflow_manifest.json` 记录失败阶段和证据，不将不完整结果宣称为成功。

## 精确层语义

候选组内按确定顺序构建森林。零件首先尝试与已有分量代表对齐；只有全部顶点在容差内一一匹配时才产生候选边。`boolean` 模式再把对齐变换作用于完整 B-Rep，计算双向差集体积：

```text
relative_error = max(volume(A-B), volume(B-A)) / max(volume(A), volume(B))
```

只有 `relative_error <= boolean_relative_tolerance` 才会联合两个节点。这个过程不使用聚类距离作为通过证据，因而能发现“向量很近但实体不全等”的假阳性。

## 迭代方法

1. 保存代表性 STEP 数据集，建立专家复核的“应合并/应分开/不确定”对照表。
2. 每次算法修改先运行单元测试，再运行小型 OCCT 集成测试，最后运行真实数据验收。
3. 对比源文件哈希、Git 版本、配置、候选组数、精确拆分数、精确层耗时、误合并和误拆分。
4. 参数调整只在固定数据切分上进行；留出数据只用于最终验证，避免对单个 `motor.STEP` 过拟合。
5. 描述符升级为自监督 B-Rep 表征时，保留现有精确层作为独立判据，不让训练模型同时充当发现器和裁判器。

## 待扩展设施

- 数据集索引与人工对照表 schema。
- 精确关系按零件哈希+容差缓存，避免重复布尔运算。
- 现有并行 OCCT 批次进一步升级为可持久作业队列，支持单对超时、重试和更粒度的失败隔离。
- 数据集级 precision/recall、簇纯度、ARI/NMI 和开集未知件指标。
